Understanding Number Bases

A number base (or radix) defines how many unique digits are used to represent numbers. Decimal uses 10 digits (0-9). Binary uses 2 (0-1). Octal uses 8 (0-7). Hexadecimal uses 16 (0-9 plus A-F). The concept is the same for all bases: each position represents a power of the base.

Decimal 255 broken down:
  2 × 10² + 5 × 10¹ + 5 × 10⁰ = 200 + 50 + 5 = 255

Binary 11111111:
  1×2⁷ + 1×2⁶ + 1×2⁵ + 1×2⁴ + 1×2³ + 1×2² + 1×2¹ + 1×2⁰
  = 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255

Hex FF:
  F×16¹ + F×16⁰ = 15×16 + 15×1 = 240 + 15 = 255

Octal 377:
  3×8² + 7×8¹ + 7×8⁰ = 192 + 56 + 7 = 255

The number 255 is the same value in every base. Only the representation changes. This is the key insight: bases are notation systems, not different kinds of numbers.

Why Developers Use Different Bases

Each base has practical advantages in specific contexts:

  • Binary (base 2) maps directly to hardware. Each digit is a bit. Bitwise operations, flags, and masks are naturally expressed in binary.
  • Octal (base 8) groups three binary digits into one octal digit. Unix file permissions use octal: chmod 755 means 111 101 101 in binary (rwx r-x r-x).
  • Hexadecimal (base 16) groups four binary digits into one hex digit. Memory addresses, color codes, and byte values are compact in hex: FF is easier to read than 11111111.
  • Decimal (base 10) is what humans think in. Port numbers, array indices, and most user-facing values use decimal.
💡 Pro Tip: The reason hex is so popular in computing is the clean mapping to binary. Each hex digit represents exactly 4 bits. A byte (8 bits) is always exactly 2 hex digits. This makes hex the most compact human-readable representation of binary data.

Common Conversion Scenarios for Developers

CSS Color Codes

Every web developer works with hex colors. Understanding the conversion helps you manipulate colors mentally. The hex color #6c5ce7 breaks down as:

#6c5ce7
 ││││││
 ││││└┘─ Blue:  0xe7 = 231
 ││└┘─── Green: 0x5c = 92
 └┘───── Red:   0x6c = 108

RGB(108, 92, 231) = #6c5ce7

Knowing that FF = 255 (maximum) and 00 = 0 (minimum) lets you read hex colors intuitively. #FF0000 is pure red. #00FF00 is pure green. #808080 is middle gray (128, 128, 128). For deeper color work, check out the AI Color Converter.

Unix File Permissions

The chmod command uses octal notation. Each digit represents three permission bits:

chmod 755 file.sh

7 = 111 (binary) = rwx (read + write + execute) → owner
5 = 101 (binary) = r-x (read + execute)         → group
5 = 101 (binary) = r-x (read + execute)         → others

Bitwise Operations and Flags

Feature flags, permission bitmasks, and hardware registers use binary. A common pattern is storing multiple boolean values in a single integer:

// Feature flags
const FEATURE_DARK_MODE  = 0b0001; // 1
const FEATURE_BETA_UI    = 0b0010; // 2
const FEATURE_ANALYTICS  = 0b0100; // 4
const FEATURE_EXPORT     = 0b1000; // 8

// User has dark mode + export enabled
const userFlags = 0b1001; // decimal 9, hex 0x9

// Check if a flag is set
if (userFlags & FEATURE_DARK_MODE) {
  // Dark mode is enabled
}

Binary literals (0b prefix) are supported in JavaScript, Python, Rust, Go, and most modern languages. But when debugging, you often see hex values in logs and need to convert them to binary to understand which flags are set.

Conversion Methods in Code

Every programming language provides built-in base conversion. Here are the most common patterns:

JavaScript

// Decimal to other bases
(255).toString(2);   // "11111111" (binary)
(255).toString(8);   // "377" (octal)
(255).toString(16);  // "ff" (hex)

// Other bases to decimal
parseInt("11111111", 2);  // 255
parseInt("377", 8);       // 255
parseInt("ff", 16);       // 255

// Hex with padding (useful for colors)
(108).toString(16).padStart(2, '0'); // "6c"

Python

# Built-in conversion functions
bin(255)    # '0b11111111'
oct(255)    # '0o377'
hex(255)    # '0xff'

# String to int with base
int('11111111', 2)   # 255
int('377', 8)        # 255
int('ff', 16)        # 255

# Format with padding
f'{255:08b}'   # '11111111' (8-digit binary)
f'{255:02x}'   # 'ff' (2-digit hex)

Common Pitfalls

Several mistakes trip up developers when working with number bases:

  • Octal literals in JavaScript: 0777 is octal in strict mode but can be ambiguous. Use 0o777 for clarity.
  • Leading zeros in JSON: 0123 is invalid JSON. JSON only supports decimal integers.
  • Case sensitivity: 0xFF and 0xff are the same value, but some tools are case-sensitive when parsing.
  • Signed vs unsigned: -1 in 8-bit unsigned binary is 11111111 (255). Two's complement representation catches many developers off guard.
  • Large numbers: JavaScript's Number type loses precision above 2^53 - 1. Use BigInt for large base conversions.

Beyond the Big Four: Custom Bases

While binary, octal, decimal, and hex cover most programming needs, other bases appear in specific domains:

  • Base 32: Used in Crockford encoding, TOTP secrets, and some URL-safe identifiers
  • Base 36: Uses 0-9 and A-Z. Compact representation for large numbers in URLs (like YouTube video IDs)
  • Base 58: Bitcoin addresses use Base58 (Base64 minus confusing characters like 0/O and l/1)
  • Base 64: Encoding binary data as ASCII text for APIs, data URIs, and email attachments. See our Base64 Guide for details.

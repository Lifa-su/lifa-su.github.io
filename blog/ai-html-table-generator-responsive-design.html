The Mobile Table Problem

HTML tables were designed for a desktop-first web. The <table> element renders as a rigid grid: every row has the same number of columns, and the browser calculates column widths based on content. On a 375px phone screen, a table designed for 1200px simply does not fit.

Common workarounds like setting font-size: 10px or width: 100% create more problems than they solve. Tiny text fails WCAG readability guidelines, and forcing a wide table into a narrow container causes content overlap. You need actual mobile friendly table patterns—not hacks.

Three Responsive Table Patterns That Work

1. Horizontal Scroll Container

The simplest and most reliable pattern: wrap the table in a scrollable container. The table keeps its natural width, and users swipe horizontally to see more columns.

.table-wrapper {
  overflow-x: auto;
  -webkit-overflow-scrolling: touch;
  border: 1px solid #1e1e2e;
  border-radius: 8px;
}

.table-wrapper table {
  min-width: 600px;
  width: 100%;
}

This works well for data-dense tables where every column matters equally. Add a subtle gradient shadow on the right edge to hint that more content is available. The AI CSS Generator can produce these scroll-hint effects with a single prompt.

2. Stacked Card Layout

For tables with fewer than 6 columns, you can reflow each row into a vertical card on small screens. Each cell displays its column header as a label using CSS ::before pseudo-elements and data-label attributes:

@media (max-width: 640px) {
  table, thead, tbody, tr, th, td {
    display: block;
  }
  thead {
    position: absolute;
    clip: rect(0 0 0 0);
  }
  td {
    padding: 8px 12px;
    padding-left: 45%;
    position: relative;
  }
  td::before {
    content: attr(data-label);
    position: absolute;
    left: 12px;
    font-weight: 600;
    color: #8888a0;
  }
}

This pattern transforms a wide table into a series of readable cards. Each row becomes its own block, with labels on the left and values on the right. It is ideal for comparison tables, contact lists, and order summaries.

3. Priority Columns

When a table has many columns but only a few are essential, hide lower-priority columns on small screens and let users toggle them:

@media (max-width: 640px) {
  .col-priority-low {
    display: none;
  }
}

@media (max-width: 480px) {
  .col-priority-medium {
    display: none;
  }
}

Pair this with a "Show all columns" toggle button for users who need the full dataset. This approach keeps the table scannable on mobile without losing information entirely.

Accessible HTML Tables: Beyond the Basics

An accessible html table is not just about adding alt text. Screen readers like NVDA, JAWS, and VoiceOver navigate tables cell by cell, announcing row and column headers for context. Without proper semantic markup, users hear a stream of disconnected values with no way to understand what each number means.

Essential Semantic Elements

  • <caption> — Provides a title for the table. Screen readers announce it before the data, giving users context. Think of it as the table’s <h2>.
  • <th scope="col"> — Marks column headers. The scope attribute tells assistive technology which cells this header describes.
  • <th scope="row"> — Marks row headers for tables where the first column labels each row (e.g., feature comparison tables).
  • <thead>, <tbody>, <tfoot> — Group rows semantically. Screen readers use these to distinguish header rows from data rows.

ARIA Attributes for Complex Tables

Simple tables with clear headers rarely need ARIA. But for complex tables with merged cells, nested headers, or interactive sorting, table accessibility aria attributes become essential:

<table role="grid" aria-label="Q4 Sales Report">
  <thead>
    <tr>
      <th scope="col" aria-sort="ascending">Region</th>
      <th scope="col" aria-sort="none">Revenue</th>
      <th scope="col" aria-sort="none">Growth</th>
    </tr>
  </thead>
</table>
  • role="grid" — Use for interactive tables with sortable columns or editable cells. For static data, the default table role is sufficient.
  • aria-sort — Indicates the current sort direction. Update it dynamically when users click column headers.
  • aria-describedby — Link to a paragraph that explains the table’s data or how to interact with it.
  • aria-colcount and aria-rowcount — Useful when the table is virtualized and only a subset of rows is rendered in the DOM.

Modern CSS Table Techniques

A well-structured css table layout goes beyond basic borders. Here are the techniques that make data tables look polished and feel usable:

Sticky Headers

When users scroll through long tables, they lose track of which column is which. Sticky headers solve this:

thead th {
  position: sticky;
  top: 0;
  background: #12121a;
  z-index: 10;
  box-shadow: 0 1px 0 #1e1e2e;
}

The header row stays fixed at the top of the viewport (or scroll container) while the body scrolls beneath it. The box-shadow creates a subtle separator so the header does not visually merge with the first data row.

Zebra Striping and Hover States

Alternating row colors help users track data across wide tables. Hover states highlight the current row for precise reading:

tbody tr:nth-child(even) {
  background: rgba(108, 92, 231, 0.05);
}

tbody tr:hover {
  background: rgba(0, 206, 201, 0.08);
  transition: background 0.15s ease;
}

Keep the contrast subtle. Heavy zebra striping competes with the data itself. A 3–5% opacity shift is enough to guide the eye without overwhelming the content.

Responsive Column Sizing

Use table-layout: fixed with percentage widths for predictable column sizing, or let the browser auto-calculate with table-layout: auto. For fine-grained control, combine min-width and max-width on <th> elements:

table {
  table-layout: fixed;
  width: 100%;
}

th:first-child { width: 30%; }
th:nth-child(2) { width: 20%; }
th:last-child { width: 50%; }

Tables vs. CSS Grid vs. Flexbox

A common question: should you use <table> elements or build table-like layouts with CSS Grid or Flexbox?

The answer depends on the content:

  • Use <table> for actual tabular data—anything where rows and columns have a meaningful relationship (spreadsheets, reports, comparisons). Screen readers understand table semantics natively.
  • Use CSS Grid for layout that looks like a table but is not data—pricing cards, feature grids, dashboard widgets. Grid gives you full control over responsive reflow without fighting table rendering. Learn more in our CSS Grid Template guide.
  • Use Flexbox for single-axis layouts—navigation bars, toolbars, or card rows that wrap. Flexbox is not designed for two-dimensional data alignment. See our Flexbox and Grid comparison for deeper guidance.

If you use CSS Grid to display tabular data, add role="table", role="row", and role="cell" ARIA roles so assistive technology can still parse the structure. But in most cases, a semantic <table> with responsive CSS is the better choice.
